# Conventions

## File Organization

### Safe to edit

- `docs/javascripts/*.js` -- client-side features
- `docs/stylesheets/*.css` -- CSS customization
- `overrides/` -- Jinja2 template overrides
- `scripts/` -- build helper scripts
- `static_content/` -- hand-authored content overrides
- `mkdocs.yml` -- MkDocs configuration
- `site.yaml` -- steel-etl site builder config

### Never edit directly (generated)

- `docs/Browse/` -- regenerated by `steel-etl site`
- `docs/Read/` -- regenerated by `steel-etl site`
- `docs/scc/` -- regenerated by `steel-etl site` (SCC redirect stubs)

To override generated content, place your file at the same relative path under `static_content/docs/`.

## Naming

- JavaScript files: kebab-case (`scc-permalink-copy.js`, `browse-enhancements.js`)
- CSS files: snake_case (`custom_font.css`, `palette.css`) -- legacy convention
- Jinja2 overrides: match mkdocs-material's naming (`main.html`, `partials/content.html`)

## MkDocs Material Overrides

When overriding material blocks in `overrides/main.html`:

- Note the material version in a comment (currently synced with 9.7.6)
- Copy the full block from material's `base.html`, then modify -- don't partially reconstruct
- Use `{{ super() }}` when extending a block rather than replacing it

## SCC Codes in Frontmatter

Every generated page has an `scc` field in its YAML frontmatter. This is the permanent identifier used for permalinks. SCC codes are frozen and must never change.

## Link Style

Internal links in generated index pages use `[Label](path/index.md)` form (not `path/`) to avoid mkdocs INFO warnings about unrecognized relative links.
