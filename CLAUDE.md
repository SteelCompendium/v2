# Steel Compendium v2

MkDocs Material site for the Draw Steel TTRPG rules reference at steelcompendium.io/v2.

## Key Rules

- **Never edit generated content directly.** Files under `docs/Browse/`, `docs/Read/`, and `docs/scc/` are wiped and regenerated by `steel-etl site`. To override a generated page, place your version at the same relative path under `static_content/docs/`.
- **Safe to edit:** `docs/javascripts/`, `docs/stylesheets/`, `overrides/`, `scripts/`, `static_content/`, `mkdocs.yml`, `site.yaml`.
- **Content source:** All rules markdown is generated by `steel-etl` from annotated source markdown. The workspace `just deploy-v2` recipe runs `steel-etl gen` (pipeline) then `steel-etl site` (MkDocs mapping). `docs/Browse/*` and `docs/Read/chapter/*` are full book-order subtree renders — each page is a direct section-mapped render of its source section's subtree produced by `RenderSubtree` (no composite reassembly step). Static overrides in `static_content/` are applied last and take precedence over generated pages. See `site.yaml` for section and group configuration.
- **Client JS must be `navigation.instant`-safe.** The site uses Material's `navigation.instant` (SPA-style body swaps). Any `docs/javascripts/` script that mounts or enhances page content must (a) register via Material's `document$` observable, **not** `DOMContentLoaded` (which fires only on the first hard load); and (b) if it reads a JSON data island, wrap the island in a `*-mount` container and find it by that container — Material recreates inline `<script>`s and strips their `class`/`type` on instant nav, so `script.<class>` selectors miss. Keep `init()` idempotent and tear down any `window`/`document` listeners it adds. **This won't reproduce on a local static serve — only on the deployed site.** Full rule + checklist: `.repo-docs/decisions/2026-06-11-client-scripts-navigation-instant.md`. **Statblocks are no longer a JSON island** (2026-06-14): they render to `.sb-wrap` HTML at build time (steel-etl `statblock_card.go`). Their client script `steel-statblock.js` is now **retired** (2026-06-18, FOLLOWUPS #10.1) — collapsible bands are native `<details>`/`<summary>` and the sticky mini-header is a CSS scroll-driven animation (`steel-statblock.css`), so the statblock **card itself** ships with no JS (interactive *tools* — scaler, dice, exports, pins, encounter-add — attach to it from their own scripts). The remaining JSON-island consumers are the Browse/bestiary search mounts; note the bestiary browser **destroys its island on mount** and republishes the parsed records as `window.SC_BESTIARY_ITEMS` — read that, not the island (see `.repo-docs/troubleshooting.md`).
- **Interactive table tools (2026-07) follow one pattern.** Pins (`sc-pins*`), encounter builder (`sc-encounter*`), dice (`sc-dice*`), exports (`sc-export.js`), scaler (`sc-scale*`): pure logic in a `<name>-core.js` UMD module tested by `node --test tests/*.test.js` (glob, not the dir — this Node rejects a directory arg), DOM wiring in the sibling mount script. Per-card page actions live in the **hover-revealed top-center control strip**, never in the head grid's column 3 (collides with the Level chip / role mini) — contract in workspace `DESIGN.md` → "Card header system". e2e checks (`tests/e2e/*.e2e.cjs`) drive Brave via playwright-core against a local build.
- **Before iterating on pseudo-element CSS, read its computed style.** Statblock features are `class="sc-ability sb__feat"`, so their `::before` is contested by *three* stylesheets (ability-card watermark, statblock watermark-kill `display:none`, flat-mode separator) — properties only the other rules declare (`display`, `opacity`, `mix-blend-mode`) win silently, and background edits apply to an invisible box. Check `getComputedStyle(el, "::before")` `.display`/`.opacity`/`.mixBlendMode` **first**; a rule that repurposes a contested pseudo-element must re-declare all three. Full writeup: `.repo-docs/troubleshooting.md` ("Statblock/ability-card CSS edits have no visible effect").
